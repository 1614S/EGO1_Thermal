> **17/18 两项的测量条件**（2026-11-21，`results/tau_theta_run.csv`）：
> 真实 XADC 模式、无风扇、gear 2（P=750 mW）；把板子靠近笔记本散热口 50 s 再移开，
> 采集 120 s。峰后降温段做指数拟合得到 τ；θ 用起点稳态 `(T0−Tamb)/P`。
> τ 与 θ 都随工况变化（自然对流随 ΔT 增强、θ 随温度下降），所以**必须写清工况**。

> **θ 与 τ 对环境温度的依赖**（2026-11-21 补充）：
> - **τ 不需要**环境温度：`analyze_thermal.py` 用 `y = A + B·e^(−t/τ)` 拟合，A（稳态值）由数据估计，
>   环境只改变曲线基准、不改变指数形状；等价的 t63 法也只需起止稳态值。
> - **θ 必须**用环境温度：`θ = (T_ss − T_amb)/P`。上面 26.47 ℃/W 是**按 Tamb = 25 ℃ 假设**算的，
>   当时 AM2302 未接；现在环境通道已实测可用（见第 2b 项），可把 `--tamb` 换成实测值。
> - 敏感度：Tamb 差 1 ℃ → θ 差约 **0.74 ℃/W（≈2.8 %）**；若实际室温 28 ℃ 而按 25 ℃ 算，
>   ΔT 高估 3 ℃ → θ 高估约 **12 %**。所以系统偏差远大于随机不确定度，
>   **接上 AM2302 后重算 θ 才有意义**。

## 2b. 上位机与交叉验证

`sw/host_logger.py`（从 `feat/waveform-tools` 分支并入）负责"串口采集 32 B 帧 → CSV"，
输出列名/单位与 `sw/analyze_thermal.py` 完全对齐（`t_s / tj_c / tset_c / duty / gear / p_mw`）。

**交叉验证**（`sw/check_frame_compat.py`，已进回归）：

把 `tb_frame` 从 RTL 里导出的整帧 hex 喂给 Python 解码器，11 个字段逐一比对：

```
seq 4660 / ts_ms 66051 / tj 50.0℃ / text 25.0℃ / rh 55.0% / tset 50.0℃
duty 500 / gear 3 / state 0 / f 100.0MHz / p 1200mW          → 全部一致
CRC 由 Python 用 binascii.crc_hqx 独立复算，也通过
```

这一步抓到了一个**真 bug**：`frame_pack` 原本直接把内部 Q8.8 的湿度发出去
（14080），而文档和上位机按"0.1 %RH"解（应为 550）—— 差 25.6 倍，湿度会显示成 1408%。
现在 RTL 里换算成 0.1 %RH 再发，两边对齐。

> 这两套实现是**独立写的**（Verilog 与 Python 各一套），它们对同一帧解出同样的数，
> 比"某一方自测通过"有说服力得多。报告里可以作为"工程规范/可复现性"的证据。

## 5. 报告里必须写的三句话

1. **虚拟热台不是"假数据"**：它替换的是器件接口层（XADC 的 DRP、AM2302 的单总线），
   下游算法/控制/遥测 RTL 一行不改；真实器件模式（`sw6=0`）走同一条数据链。
2. **三档指标是"模型在环"的结果**，不是真实热台实测；报告要写清"被控对象 = 2R2C 模型，
   参数见表"，并给不确定度讨论（τ 的拟合区间、θ 的 u(P) 主导项）。
3. **WNS/LUT 是代跑器件数据**（xc7z020clg400-1），35T 需重跑。
