## 3. 真 35T 实现：我算出的数字

命令（等价于 `scripts/build.tcl`，但用独立 TCL 从源码重建，避免依赖 `.xpr`）：

```
vivado -mode batch -source <synth+opt+place+route + report_utilization/timing_summary>
```

| 指标 | 本机（Vivado 2024.2, `-1L`） | 仓库（Vivado 2025.2, `-1L`） | 差异 |
|---|---|---|---|
| **WNS** | **+0.004 ns** | +0.156 ns | **0.152 ns** |
| 失败端点 | 0 / 6788 | 0 | 一致 |
| Slice LUT | 3726（17.91 %） | 3683（17.71 %） | 43 LUT（约 1 %） |
| Slice FF | 2462（5.92 %） | 2426（5.83 %） | 36 FF |
| DSP | 28（31.11 %） | 未列 | — |
| 布线 | Routed，约束全满足 | 同 | 一致 |

**结论**：时序在两个工具版本下都收敛，`0 违例` 这个说法成立；
但 **WNS 只有 0.004–0.156 ns，等于没有余量**。报告若写"WNS +0.156，余量充足"会站不住，
建议二选一：

1. **如实写**："真 35T、Vivado 2025.2 下 WNS +0.156 ns；另一套工具（2024.2）复算为 +0.004 ns，
   两者均 0 违例 —— 余量对工具链敏感，因此对关键路径做了保守约束。"
2. **把余量做厚**：定位 `clk_sys` 组的关键路径（本机报告里最紧的在 `clk_sys` 域），
   打一拍流水，把 WNS 拉到 > 0.2 ns。3 天内如果有余力，推荐这条。

### 4.2 `results/` 被忽略，实测 CSV 不会进仓库

`.gitignore` 里有 `results/`。交接说明 §6 把"板上实测 CSV"指向 `results/`，

### 4.3 器件口径

- 架构文档 `docs/01` 头写 `XC7A35T-1CSG324C`；
- 实际上板与报告初稿用的是 **`xc7a35ticsg324-1L`**（工业级、低功耗 `-1L` 速度等级）。

这不是笔误级的小事：`-1` 与 `-1L` 的速度等级不同，WNS 不可直接比较
（我 11/15 用 `-1` 跑出 −0.884 ns，换 `-1L` 后是 +0.004，器件不同会误导）。
**建议**：所有引用 WNS 的地方注明 part 全名。

### 4.4 回归耗时声明

交接说明写"约 5 分钟"，本机实测约 19 分钟（`tb_closed_loop` 单项 >10 分钟）。
不影响功能，但**"5 分钟"会让人以为挂死了**。建议改成"5–20 分钟，取决于机器；慢的主要是 tb_closed_loop"。
