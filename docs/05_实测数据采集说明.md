# 实测数据采集说明（上板那一次，别白采）

> 目的：把"上板采数据"这件事固定成一条命令 + 一张验收表。
> 数据格式和管理脚本对不上，就得重新上板 —— 实验室时间是最贵的。
>
> 对应提交要求里的 **必做 b（三档阶跃曲线 + CSV）** 和 **必做 c（30 min 连续记录）**。

---

## 0. 为什么单独写这份

`frame_pack.v` 发的是 **32 B 二进制帧**（A5 5A 开头，CRC16 覆盖字节 2–29）。
用串口助手直接看是乱码，用文本模式保存更是没法分析。

所以配了 `sw/host_logger.py`：**一条命令 → 一帧不差地解成 CSV**，输出列名与
`sw/analyze_thermal.py` 严格对齐，采完直接能算 τ、θ 和阶跃指标。

## 1. 采集前准备（5 分钟）

| 步骤 | 命令 / 操作 | 判据 |
|---|---|---|
| 1 | 烧 bit：`scripts\build.bat` 后下载 `Thermal.runs\impl_1\ego1_thermal_top.bit` | 板上心跳灯在闪 |
| 2 | 找 COM 口：设备管理器 → 端口 | 记下 COMx |
| 3 | 装依赖：`pip install pyserial` | 无报错 |
| 4 | **先自检**：`python sw\host_logger.py --selftest` | 输出 `[PASS]`（不需要板子） |
| 5 | 试采 10 s：`python sw\host_logger.py --port COM5 --csv test.csv --duration 10` | 约 100 帧（10 Hz） |

> 试采这一步不要跳过。**帧率不是 10 Hz 就说明时钟/帧调度有问题**，这时候采 30 min 是浪费。

## 2. 四次采集（报告就靠这四个文件）

```bat
:: ① 40 ℃ 档阶跃
python sw\host_logger.py --port COM5 --csv results\step_40C.csv ^
       --tamb 24.5 --p-mw 1200 --note "setpoint 40C gear3, 前10min自然冷却"

:: ② 50 ℃ 档
python sw\host_logger.py --port COM5 --csv results\step_50C.csv ^
       --tamb 24.8 --p-mw 1200 --note "setpoint 50C gear3"

:: ③ 60 ℃ 档
python sw\host_logger.py --port COM5 --csv results\step_60C.csv ^
       --tamb 25.1 --p-mw 1200 --note "setpoint 60C gear4"

:: ④ 30 min 长跑（自动停）
python sw\host_logger.py --port COM5 --csv results\soak_30min.csv ^
       --duration 1800 --tamb 25.0 --p-mw 1200 --note "50C 稳态长跑"
```

**每次采集必须记三个数**（写进 `--tamb` / `--p-mw` / `--note`，脚本会存成 `.meta.json`）：

| 参数 | 从哪来 | 为什么要 |
|---|---|---|
| 环境温度 Tamb | 独立温度计（手机/温湿度计都行） | §f 的 θ = ΔT/P 的分母，没有它算不了热阻 |
| 功率 P | 见第 4 节 | θ 的不确定度主要来自这里（25 %） |
| 初始条件 | 热了多久、风扇开没开 | 阶跃响应必须有明确的 t0 状态，否则拟合无意义 |

---

## 3. 采集时的三条纪律

1. **阶跃前先稳 3–5 分钟**再开始录 —— 否则 τ 拟合会把"上电瞬态"当成阶跃响应。
2. **采集期间不要开 Vivado 下载、不要开串口助手**（同一个 COM 口被占会直接断流）。
3. **录到稳态再停**：至少看到温度曲线在 ±0.3 ℃ 内平 2 分钟。经验上 ≥10τ。

---

## 4. 功率 P 怎么来（认真对待这一项）

`θ = ΔT/P` 里，`P` 的不确定度直接决定结论的可信度。三个来源：**UART 帧里的 `P_EST`**、**XPE 估算**、**实测电流**。

**最小可行做法（选一个）**：

- 省事：用帧里的 `P_EST`（mW），它来自 `activity_counter` 的功率代理，标定一次即可；
- 更硬：万用表测 VCCINT 电流，`P = 1.0 V × I`（EGO1 上有功耗测试点，见手册"隐藏的功耗测试彩蛋"）；
- 最省事：直接用 `--p-mw` 填一个 XPE 算出来的值，并在报告里说明这是估算。

> 报告 §f 要写不确定度来源，**写"P 是 XPE 估算，u(P)/P≈25 %"是完全可接受的**，
> 但必须写；不写才是硬伤。

## 5. 采完立刻自检（30 秒，别等第二天）

```bat
python -c "import csv;r=list(csv.DictReader(open('results\\step_50C.csv',encoding='utf-8')));\
s=[int(x['seq']) for x in r];\
print('行数',len(r),'时长',r[-1]['t_s'],'丢序',sum(1 for a,b in zip(s,s[1:]) if (a+1)%65536!=b))"
```

判据：

| 检查项 | 合格线 | 不合格说明 |
|---|---|---|
| 行数 | 时长 × 10 ± 5 % | 帧率不对，查 `SAMPLE_MS` |
| 丢序 | 0 | 串口丢帧，降低采样或换 USB 口 |
| `t_s` 单调 | 是 | 时间戳异常，查 32 bit 计数 |
| `duty` 范围 | 0–1000 | 若全是 0/1000，PI 饱和了 |
| `tj_c` 范围 | 20–80 | 超范围说明换算或标定有问题 |

```bat

python sw\analyze_thermal.py --csv results\step_50C.csv --out docs\figs --tamb 24.8 --p-mw 1200
```

输出：

四个 CSV + 四张图 + `*.meta.json` 直接对应报告 §c、§f 和三档曲线。

## 7. 常见失败与对策

| 现象 | 最可能原因 | 查哪 |
|---|---|---|
| 一帧都收不到 | TX/RX 接反（帧里的 `uart_tx` 是 FPGA 的 T4） | 回环测：发 `?` 看有没有回 |
| 全是乱码/CRC 全错 | 波特率不对（必须 115200） | 分频常数 `UART_DIV` |
| 帧数只有一半 | 上位机读得慢，缓冲区溢出 | 加大读缓冲 / 关掉其它串口程序 |
| `t_s` 跳变 | 32 bit 计数回绕（49 天才回绕，不太可能） | 看 `seq` 是否连续 |
| 温度不动 | AM2301 老化/没接，`age` 会一直涨 | CSV 里的 `age` 列 |
