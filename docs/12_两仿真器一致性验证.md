# 两仿真器一致性验证（闭环超调差异排查）

> 起因：队友反馈"同一套回归，xsim 跑出 60 ℃ 超调 10.3 %（超指标），iverilog 只有 9.3 %"。
> 日期：2026-11-19　结论：**仿真器语义差异被排除**，问题在两边的"输入"不同。

---

## 1. 怎么测的

从 `sim/tb/tb_closed_loop.sv` 派生了一个**双采样**副本：

- 同一次运行里，每个 `posedge tick_ms` 记两份样本：
  - `a`：沿后**立刻**读 `tj_filt`（仓库现状写法）
  - `b`：沿后 `#1` 再读（确定化写法）
- 三档缩短为 30 / 30 / 90 s（只为对比一致性，**不用于指标判分**）

如果 `a` 与 `b` 在两个仿真器下给出不同结果，就说明存在采样竞态；
如果两边、两种写法都一致，就说明仿真器语义不是原因。

编译/运行参数与 `scripts/regress.bat` 完全一致（`-g2012 -DSIM_MODEL`，无额外 `+KP/+KI`）。

## 2. 结果

| 阶段 | iverilog `ovs_a` / `ovs_b` | xsim `ovs_a` / `ovs_b` |
|---|---|---|
| 40 ℃ | 1.63 % / 1.63 % | **1.63 % / 1.63 %** |
| 50 ℃ | 1.66 % / 1.66 % | **1.66 % / 1.66 %** |
| 60 ℃ | 8.48 % / 8.48 % | **8.48 % / 8.48 %** |

连中间量都完全一致（`T0=0.81 / 40.56 / 50.00`，`Tmax=40.641 / 50.156 / 60.848`，`settle=19.2 / 15.2 / 23.1`）。

**两层结论**：

1. `a == b`（同一仿真器内）→ 在 `posedge tick_ms` 同一拍读 `tj_filt` **不构成竞态**，
   因为该拍读到的稳定是"上一拍的值"，两个仿真器都这么认为。
2. iverilog == xsim（逐位相同）→ **仿真器语义差异不能解释 9.3 % / 10.3 %**。

## 3. 那差异来自哪

既然 RTL 与 TB 都是确定的，剩下只能是"两次运行不是同一个输入"。按可能性排序：

| 可能 | 怎么查 |
|---|---|
| 两次用的 **commit 不同**（期间改过 `pi_ctrl`/前馈/滤波） | 两边各打一行 `git rev-parse --short HEAD` |
| 两次带的 **plusargs 不同**（TB 支持 `+KP=` / `+KI=`） | 把 `KP/KI` 打印出来对比 |
| 两次的 **文件集不同**（xsim 用 `filelist.f`，iverilog 用 `regress.bat` 的 glob；`filelist.f` 只有 27 行，可能漏了新模块） | 对比"实际参与编译的文件列表" |
| **`SIM_ACCEL` 不同**（`-DSIM_ACCEL=...`，regress.bat 第三个参数会传） | 打印 `SIM_ACCEL` 的宏值 |

> 其中最可疑的是**第三条**：`sim/filelist.f` 是 27 行的手工清单，而 `regress.bat` 用
> `rtl/*/*.v` 通配。若 `filelist.f` 没跟上新增的 `rtl/vplant/*.v` 或某个模块，
> xsim 编出来的设计就和 iverilog 不是同一个东西 —— 超调差 1 % 完全可能。

## 4. 建议动作

1. **两边各打印 `KP/KI/ACCEL/HEAD/参与编译的文件数`**，先证明"跑的是同一个东西"；
2. 若确认文件集不同，把 `filelist.f` 改成与 `regress.bat` 一致的 glob，或在回归里自动生成；
3. 只有在上面都一致、结果仍不同时，才需要怀疑仿真器语义——目前证据不支持这一条。

## 5. 附：本次实验的命令

```bat
:: iverilog

         rtl/*/*.v sim/models/*.v .work/tb_race.sv

:: xsim
xvlog -sv -d SIM_MODEL -i rtl/pkg -i rtl/vplant -i sim/tb rtl/*/*.v sim/models/*.v .work/tb_race.sv
xelab tb_race -s race_sim -timescale 1ns/1ps
xsim race_sim -runall
```
