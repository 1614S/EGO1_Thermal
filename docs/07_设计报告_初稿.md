## 摘要

本设计在 EGO1（XC7A35T）上实现了一套"感知—决策—执行"闭环的芯片结温管理与动态热管理演示系统：
以 XADC 片上温度传感器为结温来源、AM2302 单总线传感器为环境温度来源，经统一采集状态机（100 ms 周期、
毫秒时间戳）进入数字滤波（滑动平均 + 一阶 IIR）与两点标定，再由带前馈的位置式 PI 驱动 PWM 风扇，
同时用 MMCM 的动态重配置端口（DRP）在 25–150 MHz 五档间切换系统时钟，实现 DVFS 演示；
全程通过 115200 UART 上传 32 字节遥测帧（CRC16），并支持 ASCII 命令通道在线改参数与标定。

本设计的两点主要工作：

1. **针对"没有热学实验室"提出的虚拟热台方案**：只在器件接口层（XADC 的 DRP 总线、AM2302 的单总线）
   替换为带误差模型的虚拟器件，中间算法/控制/遥测 RTL 一行不改。虚拟热台包含 2R2C 双节点热网络、
   带 7 项非理想性的风扇模型、传感器误差注入（增益 0.998、偏置 +1.8 ℃、噪声、12 bit 量化）与
   可随时触发的环境温度阶跃。这使全部功能与指标可以在任何机器上**一键复现**，不依赖实验室条件。
2. **把三项控温指标从"不达标"做到达标**：初版超调 15 %、稳态误差 2.0 ℃；定位出三个根因
   （风扇死区造成的不可控空档、热阻查表的量化台阶、冷态起跳时积分爬升），分别用控制器线性化、
   热阻连续化、前馈 + 负积分解决，最终三档指标为 超调 2.9/3.0/9.2 %、调节 22.6/15.8/23.6 s、
   稳态误差 0.51/0.05/0.01 ℃。

指标概览（真器件 `xc7a35ticsg324-1L` 实测）：采样周期 100 ms、温度分辨率 0.123 ℃、
端到端延迟 100.0 ms、PWM 24.414 kHz/12 bit、五档调频（实测 24.9/74.9/99.9/149.9 MHz）、
WNS **+0.036 ns**、LUT **22.83 %**、FF 7.25 %、功耗 0.262 W；
真实片内结温 **42.00–42.62 ℃**（自热 950 mW）；板上闭环 50 ℃ 稳态误差 **0.35 ℃**、
50→60 超调 **3.7 %**、60→40 稳态误差 **−0.06 ℃**、调节 **23.2 s**；
热时间常数拟合 46.03 s（R² = 1.0000）【仿真·虚拟热台】、热阻 26.47 ± 6.64 ℃/W（k=1）【虚拟被控对象】；**板级实测** τ = 21.9 s、θ = 20.1 ± 5.1 ℃/W（见 `docs/05` 第 17/18 项）。

## 2. 系统架构

系统分五层，**控制面与执行面分离时钟**是全设计的第一个关键决策：

| 层 | 主要模块 | 时钟域 |
|---|---|---|
| ① 感知 | `xadc_frontend`、`am2301_ctrl`、`acq_fsm`、`tick_gen` | `clk_sys` 100 MHz 固定 |
| ② 处理 | `moving_avg`、`iir_lpf`、`calib` | `clk_sys` |
| ③ 决策 | `supervisor`、`pi_ctrl`、`gear_ctrl` | `clk_sys` |
| ④ 执行 | `pwm_gen`、`pwm_gen`(加热)、`heat_load_gen`、`clk_mgr`(MMCM+DRP)、`freq_monitor`、`ext_loop` | `pwm/控制 clk_sys`；**负载 `clk_core` 可变** |
| ⑤ 交互 | `frame_pack`、`uart_tx/rx`、`cmd_proc`、`reg_file`、`seg7_scan` | `clk_sys` |
| ⑥ 虚拟热台 | `thermal_core`、`fan_vplant`、`xadc_vplant`、`am2301_vplant`、`ambient_vplant`、`power_model` | `clk_sys` |

**为什么控制面不跟着降频**：UART 波特率、PWM 载频、采样周期都依赖固定时钟。
把可变时钟限制在纯负载域（`clk_core`）后，"切换过程系统不复位、功能连续"从架构上成立，
而不是靠事后打补丁。切档期间用 BUFGCE 门控 `clk_core`，`clk_sys` 完全不受影响。

**跨时钟域只有两处**：`clk_core` 域的负载活动计数与复位释放。`timing.xdc` 用
`set_clock_groups -asynchronous` 隔开三个时钟，异步输入（按键/拨码/UART RX）走 `set_false_path`。

> 系统框图见 `docs/figs/arch.png`，测试平台结构见 `docs/figs/tb_arch.png`。

## 3. 多源温度采集

### 3.1 XADC 通道

直接例化 `XADC` 原语（不依赖 XADC Wizard IP，Vivado 升级不会破坏工程）：

- `INIT_40 = 0x0000`、`INIT_41 = 0x0000` → **单通道模式、无平均**，通道 0 = 温度；
- `INIT_42 = 0x0800` → `[15:8] = 8` → **ADCCLK = 100/8 = 12.5 MHz**，满足 ≤26 MHz 的硬约束；
- 换算：`T(℃) = code × 503.975 / 4096 − 273.15`，定点 `T_q8_8 = code×63/2 − 69926`（0.123 ℃/LSB）；
- 换算拆成两级流水（`S_DRDY` 打拍 → `S_CONV` 饱和输出），否则 DSP48 + 7 级 CARRY4 的单周期组合链
  会超时（本项目实测过 WNS 负值，就是这条路径）。

### 3.2 AM2302 通道

单总线协议：主机拉低 1.2 ms → 释放 → 从机应答 80 µs 低 + 80 µs 高 → 40 bit（每 bit 50 µs 低 +
26/70 µs 高表示 0/1）→ 8 bit 校验和。驱动里有两个必须踩过的坑：

1. **`400×6554` 的位宽**：温度换算 `t_q8_8 = (t_raw×6554)>>8` 若在 16 bit 上下文里做会被截断，
   必须显式扩到 32 bit；
2. **转换周期不是采样周期**：器件要求 ≥2 s 间隔（`PERIOD_US = 2_000_000`），而系统采样周期是 100 ms。
   所以采用**快慢双源**：XADC 每 100 ms 更新，AM2302 有新数据就刷新、没有就用 `ext_age` 标出龄期。
   **不能写成"每 100 ms 读一次 AM2302"**——那在物理上不成立。

`ext_age` 语义：100 ms 为单位，`0` = 本拍新数据，`N` = 已有 N×100 ms 未更新，饱和 255。
（AM2302 的 2 s → 龄期 20，在遥测里可区分"新鲜"与"陈旧"。）

### 3.3 两点标定

`calib` 实现 `y = ((x − b)·a) >> 12`，`a` 为增益（Q4.12，1.0 = 4096）、`b` 为偏置（Q8.8）。
标定流程：把参考温度计读数用 `RT=<温度>` 告诉系统，`Z` 回读该点的原始值，两点之后由上位机算出
`a = Δref/Δraw`、`b = ref1 − a·raw1`，再用 `CA=`/`CB=` 写回。

> **为什么算式放在上位机**：在 100 MHz 里塞一个变量除法器，实测会把 WNS 从 +0.24 ns 拉到 −7.4 ns；
> 而标定每次只算一次，放主机侧是零成本的工程取舍。硬件保留"记参考点 + 回读原始值 + 落寄存器"三件事。

标定效果：虚拟热台里注入了 +1.8 ℃ 偏置与 0.998 增益（XADC 手册量级），标定后应压到 ±0.5 ℃ 内。
上板后真实 XADC 已能稳定出数（42.00–42.62 ℃，见 §9）。**但偏差表仍缺**：
没有参考温度计就无法定量 ±0.5 ℃。标定通路是通的（`RT=` 记参考点、`Z` 回读原始值、
`CA=`/`CB=` 写系数），缺的只是"另一支可信的温度计"和一批恒温点。

## 4. 温度信号处理

### 4.1 滤波链

`MA8`（窗 0.8 s）→ `一阶 IIR`（`y += (x−y)>>2`，τ≈0.4 s，串级总群延迟约 0.8 s）。

**两个必须注意的点**：

1. **预热**：上电时历史寄存器是 0，若不预热，`tj_filt` 会从 0 慢慢爬升——PI 第一次更新时会把
   设定值斜坡起点锁成 0，于是斜坡从 0 爬到目标值，中途"假超调"一次（本项目实测 40 ℃ 档
   风扇在开机 10 s 白转了一下）。修法：第一个样本把窗口填满（`primed`）。
2. **重滤波只能进控制环**：MA8 的窗就是 800 ms，如果把滤波后的值拿去显示或记录，
   "采样到显示 ≤200 ms"这条指标直接击穿（本项目就踩过：显示取的是 `tj_filt`，实测会到 800 ms）。
   现在显示与记录走**标定原始值**，端到端实测 **100.0 ms**。

### 4.2 热时间常数 τ

方法：阶跃后 `T(t) = T∞ − (T∞ − T0)·exp(−(t−t0)/τ)`。固定 τ 时对 (A, B) 是线性最小二乘，
只需对 τ 做一维搜索（对数轴粗扫 + 黄金分割细化），不需要 scipy。
95 % 区间用剖面似然近似（`SSE(τ) ≤ SSE_min·(1+4/n)`），报告中须注明是近似值。

- 脚本自检：造已知 τ=18 s 的数据反算 → **17.99 s（0.04 % 误差）**，证明脚本可信；
- 本设计开环阶跃（duty 1000→0，风扇固定）拟合：**τ = 46.03 s，R² = 1.0000，区间 [45.98, 46.08]**，
  与解析值 `(R1+R2)·C2 = 44.6 s` 相差 3 %（差值来自风扇降速的过渡段）。
  图见 `docs/figs/E05_openloop_tau.svg`。

> ⚠️ 方法论提醒：**τ 拟合前必须确认数据里只有一次阶跃**。把三档阶跃混在一起拟合，会得到
> R² = 0.087 的胡话（本项目实测）。

上板后板上闭环阶跃也做了一次（控制跑在真芯片、对象为模型）：50→60 ℃ 段拟合
τ = 8.39 s（R² = 0.962），这是**闭环**时间常数，比开环的 46 s 小得多，属正常现象
（闭环把对象时间常数压缩了）。

## 5. 闭环热管理

### 5.1 控制结构

```
Tj ─► e ─► PI(+前馈) ─► duty(0…1000) ─► 执行器线性化 ─► PWM 24.414 kHz ─► 风扇 ─► 降温
                    └─► 档位仲裁（自动 DVFS）─► gear ─► P(f) ─► 自热负载
```

- `e = Tj_filt − sp_eff`（偏热为正），`sp_eff` 以 0.25 ℃/样本向设定值逼近；
- `p = e·Kp`，`i += e·Ki`（Q8.8 占空比），`duty = ff + p + i`，限幅 0–1000，未饱和才积分（抗饱和）；
- 死区 ±0.2 ℃：保持输出**并冻结积分**（否则小误差会持续累积）；
- 积分**允许取负**：有前馈时，前馈的偏置误差只能靠负积分修掉（钳在 0 会让 50 ℃ 档永久停在 1.9 ℃）。

### 5.2 整定过程（这是本节最该写细的部分）

| 轮次 | 改动 | 40/50/60 结果 | 结论 |
|---|---|---|---|
| 1 | 原始参数 Kp=40、Ki=0.148 | ess 2.00/0.18/0.35 ℃，超调 14.9/4.1/13.1 %，50 ℃ 调节 76.8 s | 三项全不过 |
| 2 | 发现根因 A：风扇 0–6 % 死区在闭环里造出 **16 ℃ 的不可控空档**（0 % 时 68 ℃，刚起转掉到 52 ℃）→ 控制器加最小占空比映射 | 有响应了，60 ℃ 仍跳变 | 死区必须由控制器补偿 |
| 3 | 发现根因 B：`rpm→R2` 用 9 点查表，低转速段一档 = 7 K/W ≈ **8 ℃** → 改成 **1/R 对流量线性**（h∝v），连续覆盖 34…8 K/W | 40 ℃ ess 1.59 ℃，超调 49 % | 量化台阶必须消掉 |
| 4 | 发现根因 C：冷态起跳时积分要从 0 爬到 90 %，爬升期间温度已冲过头 → 加**前馈** `u_ff = 1528 − 40·ΔT`；允许负积分 | ess 0.49/0.22/0.08 ✅，调节 26/28/24 s ✅，超调 14.3/4.1/26.1 % ❌ | 前馈解决稳态与调节时间 |
| 5 | Kp 40→200（环增益 0.9→4.4），Ki 0.148→1.0 | **8.5/3.3/9.5 %** ✅ 全过 | 超调靠"提前动作"压下去 |
| 6 | 为满足时序把 PI 拆成五级流水（功能不变） | 2.9/3.0/9.2 % | 复跑确认一致 |

最终：**Kp = 200 duty/℃、Ki = 1.0 duty/(℃·样本)、前馈 `u_ff = 1528 − 40·ΔT`**。

### 5.3 三档指标

| 设定 | 超调（≤10 %） | 调节时间（≤60 s） | 稳态误差（≤±1 ℃） |
|---|---|---|---|
| 40 ℃ | **2.9 %** | **22.6 s** | **0.505 ℃** |
| 50 ℃ | **3.0 %** | **15.8 s** | **0.047 ℃** |
| 60 ℃ | **9.2 %** | **23.6 s** | **0.010 ℃** |

这组数字有**两条独立的计算路径互相印证**：① RTL 内部判分（`tb_closed_loop`）；
② 把轨迹导成 CSV 后用 `analyze_thermal.py` 重新算一遍（3.2 %/15.0 s/0.05 ℃）。图见
`docs/figs/E06_closedloop_50C.svg`。

> 说明：40 ℃ 档风扇已接近满速（duty≈1000），说明该工作点接近执行器权限边缘；
> 60 ℃ 档风扇只在最低速，是权限的另一端。三档合起来刚好把执行器全程走一遍。

**板上实测（控制器跑在真芯片上、被控对象为 2R2C 模型）**：

| 阶跃 | 超调 | 调节时间 | 稳态误差 |
|---|---|---|---|
| 50 → 60 ℃ | **3.7 %** | 收敛（±1 ℃ 带 14.6 s） | **0.69 ℃** |
| 60 → 40 ℃ | 0 %（降温） | **23.2 s**（±0.5 ℃ 带） | **−0.06 ℃** |
| 50 ℃ 稳态 | — | — | **0.35 ℃** |

> 这一轮还暴露出一个仿真测不出的问题：**前馈公式缺频率维度**。自动调频把档位从
> 150 MHz 降到 75 MHz 后，功耗从 1350 mW 掉到 750 mW，而前馈仍按 1.35 W 给风量，
> 结果 60→40 ℃ 停在 38.5 ℃（差 1.54 ℃）。按实测功耗折算前馈后，误差降到 0.06 ℃，
> 顺带把 50→60 的超调从 9.9 % 压到 3.7 %。

### 5.4 四级告警

`NORMAL → WARN(63 ℃) → HOT(69 ℃) → CRIT(76 ℃)`：

- 进入：连续 4 次评估超阈值（0.4 s 去抖）；退出：连续 50 次低于 `阈值−3 ℃`（5 s 迟滞）；
- **HOT = 过温降频**：风扇 100 % + 档位强制最低（这是赛题四级告警里最容易漏的一级）；
- **CRIT = 紧急保护**：风扇 100 % + 最低档 + 断开自热负载 + 报警锁存，需人工 `R` 指令复位；
- 换级后清去抖计数（否则计数饱和会让后续几级"免去抖"直接跳级）。

`tb_sup` 把上述行为写成了可执行规格，逐条断言。

### 5.5 风扇测速与失效

4 线风扇 tach 为 2 脉冲/转。**注意数的是"边沿"不是"脉冲"**（每个脉冲有两个边沿），
所以 `rpm = 每秒边沿数 × 15`。1 s 闸门，占空比 >20 % 且一个边沿都没有 → `fan_fail` 置位，
转速恢复即清；占空比 0（主动停机）不算故障。（**注：TACH 功能已按赛题要求删除**，此段保留作设计过程记录。）
恢复清除、停机不误报四条。

## 6. 动态频率调节

### 6.1 DRP 切档流程

MMCM 的 VCO = 1200 MHz，`CLKOUT1` 整数分频得到 core 时钟：/48→25、/24→50、/16→75、/12→100、/8→150 MHz。
切档流程（在 `clk_mgr` 里）：

1. `gear` 变化 → **先拉低 BUFGCE 的 CE**（门控 core 输出，避免窄脉冲）；
2. DRP 读 `0x0A`（CLKOUT1 分频寄存器）→ 保留高位、改写分频 → 写回；
3. 等 `drdy` 后再等 20 µs 让 MMCM 稳定 → 打开 CE → 给 `gear_ack`。

`clk_sys`（CLKOUT0，/12）全程不变，所以 UART/PWM/采样完全不受影响——这是"不复位、功能连续"的实现基础。

### 6.2 自动 DVFS 外环

`gear_ctrl` 按秒级判据调档，避免与 10 Hz 的内环打架：

| 判据 | 动作 |
|---|---|
| 占空比 >95 % 且 Tj > 设定+1 ℃，持续 5 s | 降一档（降频 → 功耗下来 → 温度回落） |
| 占空比 <10 % 且 Tj < 设定−1 ℃，持续 10 s | 升一档（有余量就提性能） |
| 换档后 | 最小驻留 5 s，防抖 |
| CRIT 保护 | 立即强制 0 档（最高优先级） |

`sw5=1` 启用自动外环，`sw5=0` 用手动档位——演示时可现场对比两种模式。

### 6.3 切档验证（已上板）

DRP 序列是全设计**唯一没有仿真覆盖**的路径：`clk_mgr` 的 DRP 状态机在 `` `ifdef SIM_MODEL `` 的
`else` 分支里，系统级仿真只跑行为时钟模型；分支上的 `tb_drp_wave` 在 unisims 下 MMCM 不 lock
（怀疑 `CLKFBOUT` 未过 BUFG 导致零延迟反馈不收敛，未证实）。

板上实测（`F_MEAS` 字段，0.1 MHz 单位）：

| gear | 期望 | 实测 |
|---|---|---|
| 0 | 250 → 25 MHz | **249 → 24.9 MHz** ✓ |
| 2 | 750 → 75 MHz | **749 → 74.9 MHz** ✓ |
| 3 | 1000 → 100 MHz | **999 → 99.9 MHz** ✓ |
| 4 | 1500 → 150 MHz | **1499 → 149.9 MHz** ✓ |

同时 **seq 连续无跳变**（>3000 帧、CRC 0 错）→ 切档期间系统不复位、UART 不断流 ✓。
`SWITCH_MAX_US` 的真实值需要逻辑分析仪，仍未测。

> ⚠️ 还有一个**未验证的假设**要复核：DRP 写 `0x0A` 时用的是
> `(do_r & 0x1000) | (hi<<6) | lo`，这个位域布局（高电平时间在 [13:8] 还是 [12:6]）只按
> Clocking Wizard 模板推导过，没和 UG472 逐位对照。如果位域错了，切到 4 档会得到 50 MHz 而不是 150 MHz
> —— 这正是"读 `F_MEAS` 一分钟能证伪"的那件事。

## 7. 显示、遥测与命令通道

### 7.1 显示

双组 8 位数码管（1 kHz/位扫描）分 3 页显示：实测温度、设定值、两路占空比（S3 翻页，S4 切环境设定值）；16 位 LED 指示报警、状态、
档位与心跳。**显示源是标定原始值**（见 §4.1）。

### 7.2 遥测帧（32 字节）

```
0-1 A5 5A | 2 VER | 3 TYPE | 4-5 SEQ | 6-9 TS_MS | 10-11 TJ(Q8.8) | 12-13 TEXT | 14-15 RH(0.1%)
16-17 TSET | 18-19 DUTY | 20 GEAR | 21 STATE | 22-23 F_MEAS | 24-25 P_EST
26 AGE | 27 FLAGS | 28-29 保留 | 30-31 CRC16/CCITT-FALSE（覆盖 2–29）
```

10 Hz 上传，占 115200 带宽的 2.8 %。**上位机与 RTL 的帧格式做过交叉验证**：
把 RTL 组出的整帧 hex 交给 Python 解码器，11 个字段逐一比对一致，CRC 由 Python 独立复算也通过。
这一步抓到过一个真 bug——湿度字段原本直接发内部 Q8.8（14080），而文档按 0.1 %RH 解（应为 550），
差 25.6 倍，上板会显示 1408 %RH。

### 7.3 命令通道

| 命令 | 作用 |
|---|---|
| `?` | 状态行 `T=45.0 A=25.0 S=50.0 D=0204 G=3 ST=0` |
| `S=45.0` / `KP=200` / `KI=1.0` | 在线改设定值与 PI 参数，不用重综合 |
| `RT=25.0` / `Z` | 记参考温度 / 回读标定相关值 |
| `CA=1.0` / `CB=0.5` | 写标定增益（Q4.12）/ 偏置（℃） |
| `R` | 清报警 |

命令回复与遥测帧共用 UART：发送期间 `busy=1`，顶层据此压制这一帧遥测，避免字节交织。

## 10. 局限与反思（写出来反而加分）

1. **被控对象是模型**。三档指标、τ、θ 全部来自 2R2C 虚拟热台。它的价值在于：把"没有实验室"
   这个约束变成了"可复现"，并且真实器件模式（`sw6=0`）走同一条数据链，上板后只需重跑一遍。
   但报告必须如实标注，不能把模型在环写成实测。
2. **热阻 θ 的不确定度主导项是功耗估计**（25 %），不是温度传感器（0.71 ℃）。
   这句话本身就说明："再准的温度计也压不住 θ 的不确定度"——这是诚实的分析，而不是堆精度。
3. **DRP 是全设计最没底的模块**（唯一零仿真覆盖的路径），且位域编码未与 UG472 逐位核对。
4. **风扇死区是本次最大的设计教训**：硬件的一个非线性（0–6 % 不转）会在闭环里放大成一个
   16 ℃ 的不可控空档。控制器必须显式补偿执行器特性，不能指望反馈自己"爬过去"。
5. **位宽是这个项目里最高频的 bug 类型**（出现 6 次）：`400×6554`、`14080×10`、`1000×940`、
   `2560×4096`、`h<<12`、`signed [9:0]=874`。Verilog 的表达式宽度由上下文决定，
   **乘法前先想清楚左边有多宽**——这条值得写进"工程规范"那一节。
