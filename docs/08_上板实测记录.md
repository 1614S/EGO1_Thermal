## 2. 上板抓出的 10 个 bug（仿真全部测不出）

这五条是这份记录的核心。共同点：**仿真里都有 `ifdef SIM_MODEL` 或加速宏把它们盖住了。**

### B-1　`SIM_ACCEL` 默认值漏进硬件构建

```verilog
// rtl/pkg/ego1_thermal_pkg.vh（修改前）
`ifndef SIM_ACCEL
  `define SIM_ACCEL   1000        // ← 无条件给 1000
`endif
```

硬件构建不带 `-DSIM_ACCEL`，于是 `MS_DIV = 100000/1000 = 100` → **tick_ms 变 1 µs，快 1000 倍**。

- 现象：帧率 **357 帧/s**（正好是 UART 连发极限 32B×10bit/115200=2.78 ms）；XADC 来不及转换，温度直接读 125 ℃ 饱和（当时还没意识到是两个独立问题）。
- 为什么仿真测不出：所有仿真都显式传 `-DSIM_ACCEL`，`ifndef` 那条分支永远不生效。
- 修复：按 `SIM_MODEL` 分情况默认（仿真 1000 / 硬件 1）。

### B-2　`led[7]` 被两个 `assign` 同时驱动

```verilog
assign led[7:4] = {1'b0, gear};   // 这一句已经写了 led[7] = 0
assign led[7]   = fan_fail;       // 又写一次 → 多驱动
```

- 现象：综合报 `multi-driven net ... 2nd driver pin 'GND'`，`fan_fail` 被常量吃掉，风扇故障灯永远不亮。
- 修复：`assign led[6:4] = gear;`。

### B-3　XADC 三个配置寄存器全错

手写的 `INIT_40=0x0000 / INIT_41=0x0000 / INIT_42=0x0800` 让温度寄存器**永远返回 0xFFF**。

排查过程（5 次，每次都要构建 11 分钟）：

| 尝试 | 结果 | 说明 |
|---|---|---|
| `INIT_41=0x0000` 单通道，CONVST=0 | 0xFFF | 单通道模式不自动转换 |
| `INIT_41=0x1000` 连续序列 | 0x000 | 序列里没使能任何通道 |
| `INIT_41=0x1001` 加温度使能 | 0x000 | 位理解错 |
| CONVST=tick_ms（1 ms 脉冲） | 0xFFF | 触发没生效 |
| CONVSTCLK=1 MHz | 0xFFF | 同上 |

**关键判断点**：把地址改成 `0x40`（CFG0 配置寄存器）去读，读回来正是写进去的 `0x0000`
—— 证明 **DRP 通路完全正常**，问题只在"温度通道没在转换"。

**最终做法**：不再猜，用 Vivado 的 XADC Wizard 生成一份"连续序列 + 只使能温度 + DRP 接口"
的配置，把它算出来的 INIT 值抄进原语例化：

```
INIT_41 = 0x31A0   SEQ=0011 连续序列 + 使能温度
INIT_42 = 0x0400   DCLK/ADCCLK 分频 = 4 → ADCCLK = 25 MHz（≤26 MHz）
INIT_48 = 0x0100   序列通道选择（原来根本没配这一项）
```

> 教训：寄存器位这种"手册上的事实"，**要么查手册表格，要么让工具生成**，靠记忆猜
> 五个小时也猜不出来。后来用 Wizard 生成只花 3 分钟。

### B-4　DRP 数据是**高位对齐**，我取了低 12 位

XADC 的测量结果放在 **DO[15:4]**（低 4 位恒 0），我按 `DO[11:0]` 取 → 码值被缩小 16 倍。

- 现象：真实模式下 Tj 在 **−40 … −3.6 ℃** 之间乱跳。
- 反推验证：观测码 0x770 → 真实码 0x977 = 2423 → `2423×503.975/4096 − 273.15 = +25 ℃`，
  物理上才合理。
- 修复：`adc_code = drp_do[15:4]`；同时把 `xadc_vplant` 和 `sim/models/xadc_model.v`
  也改成高位对齐，保证仿真/虚拟/真实三条路一致。

### B-5　前馈缺频率维度

`u_ff = 1528 − 40·(sp − Ta)` 是按 level15/150 MHz（≈1.35 W）标定的。
自动调频把档位降到 75 MHz（750 mW）后，前馈仍按全功率给 → 风量偏大 → 温度压过头 →
积分只能往负里压，压到极限就停住。

- 现象：60→40 ℃ 阶跃后**停在 38.48 ℃**（差 1.54 ℃），duty 却只有 626（没饱和）。
- 修复：按实测功耗对前馈做线性折算 `scale = p_est/1350`（Q8，限 0.25…1.25）。
- 效果：稳态误差 **1.54 ℃ → 0.06 ℃**；顺带 50→60 超调 **9.9 % → 3.7 %**。
  全功率下 scale≈1.0，仿真的三档指标完全不变（已验证）。

### B-6　数码管在 51.2 ℃ 翻回 00.0（16 位乘法溢出）

`t01 = (disp_abs * 16'd5) >> 7` 是 **16 位上下文**乘法。`disp_abs` 为 Q8.8：

```
51.2 ℃ → 13107；13107 × 5 = 65535 = 16 位满量程
52 ℃ 以上 → 乘积回绕 → 显示 00.0 重新爬升
```

- 现象：虚拟热台升到 **51 ℃ 左右显示突然变成 00.0**。
- 修复：中间量扩到 21 位 `disp_abs * 21'd5`，再取 `[19:7]`。
- 同一类溢出在 `cmd_proc.v` 还有两处（状态行 `t_tj10/t_sp10`、`put_temp`），一并改成 `×21'd5`；
  修前高温下 `?` 回复的 T 字段同样是错的。

### B-7　`led[0]` 全程不亮（接了 CRIT 锁存而不是"任意告警"）

`supervisor.alarm` 是**只在 CRIT 锁存**的信号，而 `led[0]` 直接接了它，
于是 WARN/HOT 时 `led[0]` 不亮、只有 `led[2]`（CRIT）会亮，三级告警只剩两盏灯。

- 修复：`led[0] = (state != 0)`（WARN 起亮），`alarm` 仍保留在遥测 `flags` bit0。
- 三级语义最终为：

| state | 含义 | `led[2]` | `led[1]` | `led[0]` |
|---|---|---|---|---|
| 0 | NORMAL | 0 | 0 | 0 |
| 1 | WARN（≥63 ℃） | 0 | 0 | **1** |
| 2 | HOT（≥69 ℃） | 0 | **1** | 1 |
| 3 | CRIT（≥76 ℃） | **1** | 1 | 1 |

- 板载只能验到 WARN/HOT（虚拟热台无风扇时平衡温度 ≈71 ℃，够不到 76 ℃）；
  CRIT 的 LED 映射用定向仿真确认：`NORMAL 000 → WARN 100 → HOT 110 → CRIT 111 → 降温+clr 回 000`。

### B-8　整百数值显示成 `4A.0`（`/100` 常数偏小）

十进制拆位用 `t01 × 2621 >> 18` 近似 `/100`，而 `2621/2^18 = 0.0099988 < 0.01`：

```
设定值 50.0 ℃ → t01 = 500；500 × 2621 >> 18 = 4.999 → 取整 4
→ 十位 4、个位 50−40 = 10（显示成 A）→ "4A.0"
```

- 影响：所有**整百**的 t01（50.0 / 60.0 / 70.0 ℃…），温度页和设定值页都会错。
- 修复：常数改 **2622**（0.0100021，略大于 0.01，向下取整恒正确）。
  串口 `cmd_proc` 里的同名常数早已是 2622，所以 `?` 回复一直正常，只有数码管显示路径漏改。

### B-9　占空比页过渡时冒出 `A`～`F`（乘法被上下文截断）

```verilog
wire [15:0] du_100 = (du_r * 18'd2622) >> 18;   // 乘积在 18 位上下文里被截断
wire [15:0] du_10  = (du_r * 11'd205)  >> 11;   // 16 位上下文里被截断
```

`du_r` 最大 999，`999 × 2622 = 2.6 M` 需要 **22 位**；截断后拆位结果落在 10～15，数码管显示成 `A`～`F`。

- 现象：占空比页在 `0000 ↔ 1000` 变化过程中闪出 `A`～`F`。
- 修复：乘积先落到 22 位中间量，再取高位：`du_m100[21:18]`、`du_m10[21:11]`。
- 全量程穷举验证：duty 0…1000 共 1001 个值，拆位结果全部 0～9。

### B-11　`board_step.bat` 生成的 CSV 里 `gear` 列出现 234

- 现象：跑完阶跃实验，CSV 的 `gear` 列是 234（应该是 2）。
- 根因：遥测帧改造后，第 20 字节 = `{加热占空比低5位, 档位3位}`、第 21 字节 =
  `{加热占空比高6位, 告警态2位}`；而 `scripts/board_step_test.ps1` 是**独立**的解帧实现，
  仍按 `gear = b[20]`、`state = b[21]` 直接取值 → 234 = 0b11101010。
- 修复：`gear = b[20] & 0x07`、`state = b[21] & 0x03`，同时补出 `duty_heat`/`tset_ext_c`
  两列（与 `capture_serial.ps1` 的 CSV 格式对齐），并打印档位范围做自检。
- 验证：`档位范围 : 2 ~ 2`；CSV 表头 13 列，`tset_ext_c=40.00`、`duty_heat=94`。

### B-10　S4 按键完全没反应（`btn_pulse[4]` 越界）

顶层按键去抖只声明了 4 位：

```verilog
wire [3:0] btn_pressed = ~btn[3:0];      // 只有 S0~S3
wire [3:0] btn_pulse   = btn_pressed & ~btn_d;
```

新增"用 S4 切环境设定值"时写的是 `btn_pulse[4]` —— **越界访问一位不存在的信号**，
综合后恒 0，所以 S4 按下去毫无反应（S0~S3 都正常，很容易误判成按键坏了）。

- 修复：**不动**原来的 4 位逻辑，给 S4 单独做一级边沿检测：

```verilog
reg s4_d;
always @(posedge clk_sys or negedge rst_sys_n)
    if (!rst_sys_n) s4_d <= 1'b1;     // 按键低有效，空闲为高
    else            s4_d <= btn[4];
wire s4_press = s4_d & ~btn[4];       // 高→低 = 按下
```

- **顺带踩的坑**：一开始图省事把 `btn_pressed/btn_pulse/btn_d` 直接扩成 5 位，
  结果 `tb_top_smoke` 挂了（`f_meas` 从 1499 变 999，说明 S1 升档没生效）。
  原因是改了公共路径影响了已验证行为 —— 最后退回"只给 S4 加独立检测"，
  回归立刻恢复 20/20。**教训：扩公共信号前先看有多少现有逻辑依赖它。**

## 3. 板级映射（丝印与代码是反的）

官方手册与 XDC 对照后确认：**代码里的 `sw[n]` 对应板上丝印 `SW[7-n]`**。

| 代码 | 板上丝印 | 引脚 | 用途（本设计） |
|---|---|---|---|
| `sw[0]` | SW7 | P5 | 负载级数 bit0 |
| `sw[1]` | SW6 | P4 | bit1 |
| `sw[2]` | SW5 | P3 | bit2 |
| `sw[3]` | SW4 | P2 | bit3 |
| `sw[4]` | SW3 | R2 | 数码管自检图案 `1.234`（上=自检，下=正常） |
| `sw[5]` | SW2 | M4 | 自动 DVFS 使能 |
| `sw[6]` | **SW1** | N4 | **虚拟热台 / 真实器件选择** |
| `sw[7]` | SW0 | R1 | 未用（原"外部温度"显示已并入第 3 页，由 S3 翻页） |

**演示时的推荐配置**：
- 全 ON ＝ `0xFF` → 虚拟热台 + 负载满级 + 自动调频（可复现三档指标）
- 只把 **SW1 拨 OFF** → `sw[6]=0` → 切真实 XADC（此时读数不会再受风扇影响）

## 5c. 2026-11-20 追加：数码管 / 命令通道 / 自动调频实测

### 5c.1 数码管（双组 8 位、三页显示）

**操作**：
- 按 **S3（`btn[3]`，V1）** 每按一次翻一页，三页循环；
- 按 **S4（`btn[4]`，U4）** 循环切换**环境温度设定值** 40 / 50 / 60 ℃（结温设定值仍由 S0 切 40/50/60）；清报警改用串口 `R`；
- `sw[4]`（SW3）拨上则在两组都显示自检图案 `1.234`。

> 翻页键做了 **2 级同步 + 20 ms 去抖 + 上电保护**（必须先观测到"松开"状态才允许翻页）。
> 原因：早期直接用未去抖的按键脉冲，重载比特流时 V1 的电平抖动会被当成一次按键、
> 把默认页翻走。现在重载后**必定停在第 1 页**。

| 页 | 左 4 位（`seg` + `an[3:0]`） | 右 4 位（`seg2` + `an[7:4]`） | 小数点 |
|---|---|---|---|
| 1 | 实测结温 `tj_cal` → ` 33.0` | 实测环境温度 `text_cal` → ` 21.4` | 两侧都在个位右侧 |
| 2 | 结温设定值 `setpoint` → ` 50.0` | 环境设定值 `setpoint_ext` → ` 40.0` | 同上 |
| 3 | 风扇 PWM 占空比 → `0000`/`1000` | 加热 PWM 占空比 → `0097` | 无 |

| 项 | 结论 |
|---|---|
| 极性 | EGO1 为**共阴、段选与位选都高有效**（与 `docs/09` 一致，原 RTL 按共阳写反了） |
| 位序 | 左组实测 `an[0]` 在**最左**；自左向右 = `digits[3:0] / [7:4] / [11:8] / [15:12]`；右组同构（`an[4]` 起） |
| 段选 | 两组各有独立段选总线：`seg[7:0]`（B4…D5）与 `seg2[7:0]`（D4…H2），位选由 `an[7:0]` 拼接 |
| 抖动 | 加入 XADC **8 点滑动平均**（10 ms 采样点，+35 ms）后，显示末位抖动从 ±0.5 ℃ 降到 ±0.1 ℃ |
| 显示上限 | 每位组只有 4 位，温度最多到 `99.9`；≥102.9 ℃ 拆位会越界（演示最高 71 ℃，碰不到） |
| 拆位踩坑 | 全部用扩位中间量：温度 ×5 要 21 位（51.2 ℃ 溢出）、duty ×2622 要 22 位（否则出现 A~F）、`/100` 常数必须 2622 否则整百显示 `4A.0` |

### 5c.2 命令通道（115200 8N1）

修复前 `?` 只回 15 字节乱码、`OK\r\n` 只剩 `O\r`。根因三条：发送节拍早一拍（隔字节丢）、仲裁首字节被遥测抢走、`div10/div100` 四舍五入导致个位变 10/11。修复后实测：

```
?        → T=35.7 A=22.7 S=50.0 SE=40.0 D=1000 H=0068 G=2 ST=0   （46 字节：六项数据 + 档位 + 告警态）
S=42.5   → OK
KP=120   → OK
Z        → A=1000 B=0000 R=22CE
```

### 5c.4 AM2302 接入与"只读一次"排障（2026-11-21）

接线：`VDD→3.7 V（可调电源）`、`DATA→A13`、`GND→GND`。

**现象一：上电读到一次，之后不再刷新（`age` 恒 255）**

排障过程（这条最值得记）：

1. 先把周期从 2.000 s 改到 2.5 s → 短暂好转，但后来又不刷新；
2. 给驱动加**错误计数器**（`Z` 命令回复里增加 `E=`总错误数、`C=`校验错数）：
   实测 `E` 每 2.5 s 涨 1、**`C` 恒 0** → 说明 40 bit 一个都没收到，是**协议超时而非校验失败**；
3. 量 A13 空闲电压 = **3.53 V**（正常高电平）→ 排除"传感器把总线拉死"；
4. 关键现象：**重载比特流后必须给传感器断电再上电才有读数**，之后又冻结 →
   说明**每次事务后传感器就进入不应答状态**；
5. 最终根因：**启动脉冲与超时余量太紧**（1.2 ms 启动、300 µs 超时），在 3.7 V 供电下
   （datasheet 时序按 5 V 标定）传感器来不及响应，事务被我们主动中止，传感器随之罢工。

**修复**（`am2301_ctrl.v` + 顶层周期）：

| 参数 | 旧值 | 新值 |
|---|---|---|
| 启动低电平 `C_START_LOW` | 1.2 ms | **5 ms**（器件允许 1–20 ms） |
| 响应超时 `C_TIMEOUT` | 300 µs | **1 ms** |
| 轮询周期 `EXT_PERIOD_US` | 2.0 → 2.5 s | **3.0 s** |

**验证**（传感器上电一次后）：

| 场景 | 结果 |
|---|---|
| 正常运行 60 s | `age` 13→23→3 循环、`TEXT` 23.20→23.10 连续变化、`E` 不再增长、`C`=0 |
| **重载比特流、不给传感器断电** | `age` 0→10→20→30 循环、`TEXT` 连续更新（17.24→23.09）✅ **问题消失** |

> 诊断接口：串口发 `Z` 现在会回 `A=cccc B=cccc R=cccc E=cccc C=cccc`，
> 其中 `E` = AM2302 总错误数、`C` = 校验错数（C 增长说明传感器应答了但位解码错）。

**现象二：A13 电压超IO 规格**

| VDD | A13 空闲电压 | 判定 |
|---|---|---|
| 断电 | 0.6 V | 正常（未上电芯片经 ESD 二极管钳位） |
| **5.0 V** | **3.7～3.8 V** | ❌ 模块内部上拉到 VDD，5 V 经 A13 钳位二极管压到 3.7 V，超 3.6 V 绝对最大值 |
| **3.7 V** | **3.53 V** | ✅ 安全 |

- 说明：AM2302 的 DATA 是开漏，高电平由"上拉接到哪个电源"决定；模块内部上拉接 VDD，
  所以 **VDD 必须 ≤3.6 V**（datasheet 允许 3.5～5.5 V），否则要给 A13 加电平转换。
- 3.3 V 不行：低于 datasheet 的 3.5 V 下限。

### 5c.5 板级 τ / θ 实测（外部热扰动法，2026-11-21）

**方法**：真实 XADC、无风扇、gear 2（P=750 mW）稳态运行，把板子靠近笔记本散热口约 50 s 再移开，
同时采 120 s 遥测；峰后降温段做 `y = A + B·e^(−t/τ)` 拟合，θ 用起点稳态 `(T0 − Tamb)/P`，
**Tamb 取 AM2302 实测值**（22.99 ℃）。

| 量 | 结果 |
|---|---|
| 起点稳态 T0 | 38.04 ℃ |
| 环境 Tamb | 22.99 ℃（AM2302） |
| 自热功耗 P | 750 mW |
| 峰值 | 41.20 ℃ @ 49 s |
| **τ（指数拟合）** | **21.9 s，R² = 0.9936**（A=39.23、B=2.09） |
| τ（t63 法） | 20.7 s（与拟合一致） |
| **θ** | **20.1 ± 5.1 ℃/W (k=1, rel 25.4 %)**，u(P) 主导 |

**与虚拟热台的对比**：vplant 的 τ=46.03 s 是**为让 40/50/60 三档压进 60 s 而标定的等效参数**，
不是真实板参数；真实板（裸封装、无散热片、750 mW）实测 τ≈22 s、θ≈20 ℃/W，
这也解释了为什么真实模式下很难把结温推到 60 ℃ 以上。

**复现**（2026-11-22 升级版脚本，自动生成报告/曲线/归档目录）：

```bash
# 结温通道（默认；Tamb 自动取 AM2302 初值）
python sw/fit_tau.py --csv results/tau_theta_run.csv

# 传感器通道（Tamb 必须显式给，因为 text_c 初值是它自己的自热稳态）
python sw/fit_tau.py --csv results/xxx.csv --channel text --tamb 23.0

# 不需要硬件的自检：合成已知 τ/θ 的数据，两条通道各验一次
python sw/fit_tau.py --selftest
```

每次运行会在 `results/` 下新建 `<CSV名>_<通道>_<时间戳>/`，内含：

| 文件 | 内容 |
|---|---|
| `report.md` | 估算结果表、**GUM 不确定度分解**、**τ 的 95% 置信区间**（残差自助法）、方法与假设、复现命令 |
| `curve.png` | 温度-时间曲线 + 拟合曲线 + 峰值/τ 标记 + 置信区间色带 |
| `fit.json` | 机器可读结果（便于批量汇总） |
| `<原CSV>` | 原始数据副本 |

**自检结果**（合成数据，已知真值）：

```
[PASS] 通道 tj  : tau 21.91 s (真值 21.91, 误差 0.0 %)  theta 20.00 C/W (真值 20.00, 误差 0.0 %)
[PASS] 通道 text: tau 44.86 s (真值 45.00, 误差 0.3 %)  theta 30.00 C/W (真值 30.00, 误差 0.0 %)
```

**两个分析脚本的分工（避免用错工具算出错误数字）**：

| 脚本 | 适用数据 | 输出 | 不适合的场景 |
|---|---|---|---|
| `sw/fit_tau.py` | **外部扰动** 或 **设定值阶跃**（自动判别） | 扰动→峰后段 τ；阶跃→整段 τ；均含 θ + GUM 不确定度 + 95%CI + report.md + curve.png | 数据既非单调阶跃也无中间峰时拒绝 |
| `sw/analyze_thermal.py` | **设定值阶跃**（`S=` 改目标后等它稳定） | overshoot / settle / ess + 整段 τ + SVG | 扰动数据（整段拟合会把升温段算进去，R²≈0.5、τ 偏低 25%） |

> 实测对照：同一份扰动数据 `tau_theta_run.csv`，`fit_tau` 给 **τ=21.91 s（R²=0.994）**，
> `analyze_thermal` 给 **τ=16.53 s（R²=0.519）**；而同一份阶跃数据 `to33.csv`，
> `analyze_thermal` 给 τ=70.03 s（R²=0.997），`fit_tau` 会正确拒绝。
>
**`fit_tau.py` 的数据形状自动判别**（2026-11-22 加入，避免误拒纯阶跃数据）：

| 判据 | 判定 | 拟合段 |
|---|---|---|
| 最大值出现在 8 %–92 % 位置，且峰值高于首尾两端 5σ | `disturbance` | 峰后段 |
| 分块中位数单调（≥85 % 的块间变化同向）且首尾差 >5σ | `step` | 整段（跳过前段稳态） |
| 都不满足 | `unknown` | 拒绝并提示 |

> 实测验证：`to33.csv`（阶跃）→ `step`，τ=68.70 s（`analyze_thermal` 给 70.03 s，差 1.9 %）；
> `tau_theta_run.csv`（扰动）→ `disturbance`，τ=21.91 s，与升级前完全一致。
> 阶跃模式下会额外提示"若阶跃改变的是风扇转速/档位，θ_eff 已变，θ 仅供参考"。

> 从 2026-11-22 起，`analyze_thermal` 在 R²<0.90 时会打印警告并提示改用 `fit_tau.py`，
> 不再静默给出可疑的 τ。

**数据无效时会明确拒绝**（不产出看似专业但无意义的报告）：峰值不在前段之后、峰后少于 50 帧、
扰动幅度小于 5 倍噪声、或 T0≈Tamb 时，脚本直接报错并给出排查提示。

### 5c.6a 加热装置热参数实测（2026-11-22，无 MOS 管、5 V 常通）

**装置**：10 Ω/5 W 电阻用扎带绑在 AM2302 外壳上，电阻直接接 5 V（**常通 = 2.5 W**，
与固件 PWM 无关），采 10 分钟（`results/heat_no_mos.csv`，6000 帧）。

| 量 | 实测值 | 说明 |
|---|---|---|
| 起始 / 结束温度 | 23.00 → **48.19 ℃**（+25.2 K / 10 min） | RH 53 %→35 %，确认是真加热 |
| 指数拟合 τ | **1156 s（19.3 min）** | R²=0.9715，明显偏慢 |
| 外推稳态 | 89.9 ℃（ΔT = 66.9 K） | 未真正到稳态（10 min 只到 37 %） |
| **θ_eff** | **26.7 ℃/W** | ΔT_ss / 2.5 W |
| 热容 C_th | 43 J/K（拟合）/ 831 J/K（初始斜率） | 两者差 180 % → **不是单一指数**（电阻快、传感器慢） |
| 板子结温 | 33.88 → 34.05 ℃（+0.17 K） | 热量没有漏进板子，耦合方向正确 |

**由 θ_eff 反推各档所需占空比**（5 V / 2.5 W 满量程，T_room=23 ℃）：

| 目标 | ΔT | 需要功率 | 占空比 |
|---|---|---|---|
| 40 ℃ | 17 K | 0.64 W | 25 % |
| 50 ℃ | 27 K | 1.01 W | 40 % |
| 60 ℃ | 37 K | 1.38 W | **55 %** |

**结论**：功率不是瓶颈（60 ℃ 只需 55 % 占空比），**动态太慢**才是问题——
τ≈19 min 意味着闭环要几十分钟才稳，演示不可接受。慢的根源是"扎带+空气隙"的接触热阻，
热量要穿过空气才能到传感器内部。

**由此修正固件前馈增益**：原来按 θ≈100 K/W 取 `k_ff = 4 duty/K`，
实测应为 `k_ff = 1000/(θ_eff × Pmax) = 15 duty/K`（**差 3.7 倍**），
否则 PI 要额外积 3 倍多的占空比，慢且容易饱和。已改为精确 15 duty/K（乘法实现）。

### 5c.6 环境温度闭环（AM2302 → 加热电阻，2026-11-21）

赛题"40/50/60 ℃ 三档控温"用**加热电阻**实现：10 Ω/5 W 电阻贴 AM2302，低边 N-MOS 驱动，
栅极接 FPGA 的 `heat_pwm`（**B18 / J5 第 7 脚**），新增 `SE=` 命令设目标环境温度。

**结构**（`rtl/ctrl/ext_loop.v`，复用结温环的 `pi_ctrl`）：

```
A=环境温度 → 前馈(4 duty/K × (Tset−T_room)) + PI(Kp=2, Ki=0.01, 积分分离 1 ℃) → duty → heat_pwm
```

三个关键整定点（都是仿真里试出来的）：

| 问题 | 现象 | 修法 |
|---|---|---|
| **误差方向反了** | 加热环照风扇逻辑写 → T 越低于设定值占空比越小，永远不加热 | `pi_ctrl` 加参数 `INVERT_ERROR=1` |
| **前馈参考点错** | 用"传感器自身温度"算 `(Tset−T)`，到设定值后前馈归零，稳态只能靠积分硬撑 | 前馈改用**室温参考** `(Tset−T_room)` |
| **积分饱和** | 大误差阶段积分一直积，慢对象（τ≈100 s）严重超调（75 %→38 %→23 %） | 加**积分分离** `E_ILIM=1 ℃`：误差大时冻结积分 |

**仿真结果**（`tb_ext_loop`，对象 τ=100 s、θ=100 K/W、Pmax=2.5 W）：

| 目标 | 超调 | 稳态误差 | 稳态 duty |
|---|---|---|---|
| 40 ℃ | **0.4 %** | +0.06 ℃ | 61 |
| 50 ℃ | **2.3 %** | +0.19 ℃ | 100 |
| 60 ℃ | **1.5 %** | +0.12 ℃ | 140 |

**上板验证**（暂无 MOS 管，只验控制输出）：

```
?        → T=32.0 A=21.2 S=50.0 D=1000 H=0061 G=2 ST=0
SE=50.0  → OK，随后 H 从 0045 变为 0101（前馈 4×(50−25)=100 + PI 修残差）
SE=25.0  → OK，H 变为 0007（前馈 0 + P 项）
```

- `H=` 是状态行新增的**加热占空比**字段，无 MOS 管时可用万用表量 B18 的平均电压间接验证；
- 安全门控：CRIT 告警 / 外部温度 ≥75 ℃ / 外部数据龄期 ≥10 s / 时钟未锁定时 **强制 H=0**，
  避免"告警反而猛加热"；
- `pi_ctrl` 的改动全部参数化（`INVERT_ERROR/SP_RAMP/E_ILIM` 默认值保持原风扇行为），
  结温环回归 19 项不变，新增 `tb_ext_loop` 后共 **20/20 PASS**。
